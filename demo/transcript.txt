── 8. Rate limiting is per caller ────────────────────────────────────
   One client burns its 8/min quota; another client is untouched.

   client A, attempt 1: HTTP 200   remaining: 7
   client A, attempt 2: HTTP 200   remaining: 6
   client A, attempt 3: HTTP 200   remaining: 5
   client A, attempt 4: HTTP 200   remaining: 4
   client A, attempt 5: HTTP 200   remaining: 3
   client A, attempt 6: HTTP 200   remaining: 2
   client A, attempt 7: HTTP 200   remaining: 1
   client A, attempt 8: HTTP 200   remaining: 0
   client A, attempt 9: HTTP 429   retry-after: 8s

   client B, first call:  HTTP 200   remaining: 3
   → one caller's burst cannot exhaust another caller's quota

── 9. Idempotent retries ─────────────────────────────────────────────

── 11. Graceful shutdown ─────────────────────────────────────────────
   Readiness fails first so traffic stops arriving, then in-flight requests drain.

   $ kill -TERM  (what `docker stop` and Kubernetes send)

     INFO:     Shutting down
     {"timestamp": "2026-09-16T10:21:44.162729+00:00", "level": "INFO", "logger": "app.main", "message": "shutdown complete"}
     INFO:     Application shutdown complete.

   → the shutdown hook ran and the app drained before the process exited
   → terminated by SIGTERM (exit status -15), the normal signal-death code
